# Getting help with Replay 
- For issues and feature request visit [mpvrx](https://github.com/Riteshp2001/mpvRx/issues/new?template=bug_report.md)
## Start here

- Check the [README](README.md) for features, build variants, and setup information.
- Check [release notes](https://github.com/utsavrajputt/Replay/releases) and [existing issues](https://github.com/Riteshp2001/mpvRx/issues) before opening a new report.
- When troubleshooting, note whether you are using a stable or preview build and which APK variant you installed.

## Report a bug

Use the [bug report template](https://github.com/Riteshp2001/mpvRx/issues/new?template=bug_report.md). Include:

1. App version or commit, APK variant, device model, and Android version.
2. Exact steps to reproduce the issue, followed by expected and actual behavior.
3. Relevant settings, including custom `mpv.conf`, scripts, shaders, or gesture options.
4. Screenshots, a short recording, or relevant logs when useful.

For playback problems, include the media source type, container, codecs, resolution, and whether the problem also occurs with default settings. Share only media you have permission to distribute.

For Jellyfin, Navidrome, or Subsonic issues, include the server software/version and whether the same account can play the item in another client. Never post passwords, app tokens, authenticated stream URLs, or private server details.

For navigation or performance problems, describe the exact tabs and direction, whether the problem happens on first use or repeatedly, and the approximate library size. A recording or performance trace can help distinguish gesture problems from slow loading. Review logs and traces for private information before sharing them.

## Suggest a feature

Use the [feature request template](https://github.com/Riteshp2001/mpvRx/issues/new?template=feature_request.md). Explain the problem you want to solve, who it affects, your proposed behavior, and alternatives you have tried. For larger changes, discuss the idea before spending time on an implementation.

## Ask a question

If the README and existing issues do not answer your question, [open an issue](https://github.com/Riteshp2001/mpvRx/issues/new) with a clear title and enough context to help others understand it. Keep one main topic per issue.

## Sensitive reports

Do not publish vulnerability details, exposed credentials, or private conduct reports in a public issue. Use a private contact method published by the [maintainer](https://github.com/Riteshp2001); if none is available, ask for a private reporting channel without posting the sensitive details.

For community concerns, see the [Code of Conduct](CODE_OF_CONDUCT.md).

## Respectful collaboration

Support and review depend on maintainer availability; a report does not guarantee an immediate response or implementation. Keep follow-ups relevant, avoid duplicate reports, and follow the [Code of Conduct](CODE_OF_CONDUCT.md).
